A function names a piece of work so you can call it instead of copying its lines. C makes one promise about that call and never breaks it: the function receives copies of your arguments, so it cannot touch the caller's variables unless you hand it their addresses. This chapter is about that rule and the signature vocabulary that keeps it honest.

## Objectives

- Declare a prototype above `main` and define the function below it.
- Explain why C is entirely pass-by-value: every argument arrives as a copy in a new stack frame.
- Use pointer parameters when a function must change a caller's variable or report several results.
- Pass an array to a function with its length as a `size_t`.

## Why students struggle

The surprise usually arrives in a lab. You write `void addBonus(int balance) { balance += 500; }`, call `addBonus(myBalance);`, print `myBalance`, and it is unchanged. Nothing failed and nothing warned: the function updated a photocopy in a box of its own, and that box ceased to exist at `return`.

The second difficulty is the signature. A prototype must match the definition exactly, an array parameter is really a pointer, and `int func()` in C17 means an unspecified argument list rather than none. Get one wrong and the message often points at the call site, not the cause.

## The code, both ways

Both programs do the same four things in the same order — return a computed receipt, try to change a balance by value, change it through a pointer, then sum an array — and only the nouns change.

### The money version

```c
// Money version (functions_money.c)
#include <stdio.h>

// Function prototypes (tell the compiler the signatures up front)
int computeInterestPence(int principalPence, int ratePercent);
void tryDepositByValue(int balanceCopy, int amountPence);
void depositViaSlip(int *balanceSlip, int amountPence);
int sumDeposits(const int deposits[], size_t count);

int main(void) {
    int leoBalance = 20000;   // £200.00

    // 1. Returning a calculated receipt
    int interest = computeInterestPence(leoBalance, 5);
    printf("5%% interest on %dp is %dp\n", leoBalance, interest);

    // 2. Pass-by-value (handing the clerk a PHOTOCOPY — original unchanged!)
    tryDepositByValue(leoBalance, 5000);
    printf("After tryDepositByValue: leoBalance is STILL %dp\n", leoBalance);

    // 3. Passing a pointer (handing the clerk the CLAIM SLIP — original updated!)
    depositViaSlip(&leoBalance, 5000);
    printf("After depositViaSlip:    leoBalance is NOW   %dp\n", leoBalance);

    // 4. Passing an array + its length
    int weekDeposits[4] = {1200, 800, 2500, 1500};
    printf("4-day deposit total: %dp\n", sumDeposits(weekDeposits, 4));

    return 0;
}

int computeInterestPence(int principalPence, int ratePercent) {
    return (principalPence * ratePercent) / 100;
}

void tryDepositByValue(int balanceCopy, int amountPence) {
    balanceCopy += amountPence;   // only modifies the local photocopy!
    printf("  [Inside tryDepositByValue] photocopy is %dp\n", balanceCopy);
}

void depositViaSlip(int *balanceSlip, int amountPence) {
    *balanceSlip += amountPence;  // opens the caller's vault box and adds cash!
}

int sumDeposits(const int deposits[], size_t count) {
    int total = 0;
    for (size_t i = 0; i < count; i++) {
        total += deposits[i];
    }
    return total;
}
```

### The football version

```c
// Football version (functions_football.c)
#include <stdio.h>

// Function prototypes (the team sheet handed to the referee before kick-off)
int computeLeaguePoints(int wins, int draws);
void tryAwardGoalByValue(int goalsCopy, int added);
void awardGoalViaTicket(int *goalsTicket, int added);
int sumMatchGoals(const int goals[], size_t count);

int main(void) {
    int leoGoals = 10;

    // 1. Returning a calculated result
    int pts = computeLeaguePoints(12, 5);
    printf("12 wins, 5 draws = %d league points\n", pts);

    // 2. Pass-by-value (handing the scout a PHOTO — original unchanged!)
    tryAwardGoalByValue(leoGoals, 2);
    printf("After tryAwardGoalByValue: leoGoals is STILL %d\n", leoGoals);

    // 3. Passing a pointer (handing over the SEAT TICKET — original updated!)
    awardGoalViaTicket(&leoGoals, 2);
    printf("After awardGoalViaTicket:  leoGoals is NOW   %d\n", leoGoals);

    // 4. Passing an array + its length
    int recentGoals[4] = {2, 1, 0, 3};
    printf("4-match goal total: %d\n", sumMatchGoals(recentGoals, 4));

    return 0;
}

int computeLeaguePoints(int wins, int draws) {
    return (wins * 3) + draws;
}

void tryAwardGoalByValue(int goalsCopy, int added) {
    goalsCopy += added;   // only draws on the scout's photo!
    printf("  [Inside tryAwardGoalByValue] photo shows %d\n", goalsCopy);
}

void awardGoalViaTicket(int *goalsTicket, int added) {
    *goalsTicket += added; // walks to the real seat and updates the tally!
}

int sumMatchGoals(const int goals[], size_t count) {
    int total = 0;
    for (size_t i = 0; i < count; i++) {
        total += goals[i];
    }
    return total;
}
```

```sh
cc -std=c17 -Wall -Wextra -Wpedantic -g functions_money.c -o functions_money
./functions_money
```

| Name | What it does for you |
|---|---|
| `-std=c17` | The ISO C17 standard this handbook teaches. |
| `-Wall -Wextra -Wpedantic` | Strict warnings; they catch a prototype that disagrees with its definition. |
| `-g` | Line numbers and names for the debugger. |
| `-o functions_money` | Names the executable; without it the compiler writes `a.out`. |
| `./functions_money` | Runs the binary, not the source. |

## What is really happening

**C has no pass-by-reference.** Every call copies. `depositViaSlip(&leoBalance, 5000)` copies the eight-byte address into `balanceSlip`, a local variable of that function. What makes the call useful is the kind of value copied: an address you may follow. `*balanceSlip += 5000` writes through it into `main`'s frame, which is still alive because `main` has not returned.

**Array parameters decay to pointers.** In a parameter list, `int arr[]` and `int *arr` are the same declaration; the brackets are documentation, not a type. Inside the function `arr` is an eight-byte pointer, so `sizeof(arr)` is `8`, not the array's size, which is why every array parameter here comes with `size_t count`. The `const` promises that the pointed-at integers are read-only.

**Returning several values.** A function returns one value, so extra results travel through output parameters: `void getMinMax(const int deposits[], size_t count, int *outMin, int *outMax)` writes into addresses the caller already owns.

Draw `main`'s frame beside the callee's, cross out the callee's frame at `return`, and the rule becomes obvious.

## Where the analogy stops

A bank clerk remembers your face from five minutes ago; a C function has complete amnesia between calls. At `return` its whole stack frame — desk, photocopier, claim slips — is wiped clean, and every local in it ceases to exist; only the receipt survives. A function therefore cannot accumulate state across calls unless the variable is `static`, giving it a life outside the frame (Chapter 13), and a pointer to a local dies with it: the address looks valid while the storage is gone.

## Common mistakes

- **The classic broken `swap(int a, int b)`.** The parameters are copies, so the swap succeeds inside the function and is destroyed on return. The working version takes addresses and swaps what they point at.
- **Calling `sizeof` on an array parameter.** Inside `void f(int arr[])`, `sizeof(arr)` is `8`: a pointer's width, not a length.
- **Writing `int func()` where you mean `int func(void)`.** In C17 empty parentheses in a declaration mean *unspecified* arguments, so the compiler stops checking calls.

The two swap versions, side by side:

```c
// BROKEN: only swaps the local photocopies a and b!
void brokenSwap(int a, int b) { int t = a; a = b; b = t; }

// CORRECT: swaps the caller's boxes via pointers!
void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }
```
