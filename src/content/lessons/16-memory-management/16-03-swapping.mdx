## When there are more programs than there is memory

Paging solved the layout problem. It did not solve the capacity problem.
Every program on the machine wants an address space, and the sum of
those address spaces is routinely larger than the physical memory
installed. Something has to leave.

**Swapping** is the oldest answer: move an entire process out to disk,
and move one back in when it is needed. The unit of movement is the
process. That makes the arithmetic brutal in a way the previous two
lessons were not, because the cost of a decision is proportional to a
size nobody chose — the program's footprint — and the disk is four to
five orders of magnitude slower than memory.

The historical fix was not a better eviction policy. It was a smaller
unit: **paging to disk** in 4 KB pieces, on demand, which is the subject
of the next module. Swapping survives in a narrower role — the kernel
moving whole processes aside under pressure — and if you have ever seen
a laptop freeze for twenty seconds after waking from sleep, you have met
it.

## What you'll be able to do

- Compute the I/O cost of admitting a process to a full memory.
- Explain why evicting a process that is about to run is the expensive case.
- Distinguish swapping from paging by the unit of transfer.
- Say what a small unit buys and what it costs instead.

## The admission decision

When a process must become resident and memory is full, the kernel has
three choices and none of them is free:

| Option          | Cost                                    | Consequence                    |
| --------------- | --------------------------------------- | ------------------------------ |
| Evict something | one write per evicted process           | that process must be read back |
| Refuse          | none now                                | the requester starves or waits |
| Compact         | copying within memory, no disk I/O      | only helps with free holes     |

Compaction is worth keeping in the list because it is the cheap one
when it applies: it shuffles resident regions so a free hole becomes big
enough, paying only memory bandwidth, no disk. It is also the reason the
previous lesson's fragmentation was tolerable. But compaction cannot
create memory that is not there, and once physical memory is genuinely
over-committed, one of the other two options applies.

The decision is made worse by a fact about schedulers: the process being
evicted is very often the process with the most recent evidence of being
runnable. A scheduler that round-robins between two processes, each
larger than half of memory, produces exactly the pathological pattern —
each admission evicts the other, and both live on disk.

<TheoryBlock label="Why it matters for C" title="Your process's size is not what you wrote">

	The resident set of a C program is not its text size. It includes the
	heap from `malloc`, the stack for every thread (8 MB of address space
	each by default, though only touched pages are resident), memory-mapped
	files, and the shared libraries the dynamic loader pulled in. A program
	whose source is 200 lines can easily be 8 MB resident. This matters
	when you measure: `time -l` on macOS or `/usr/bin/time -v` on Linux
	reports maximum resident set size, and that number — not the size of
	the binary — is what a swapping kernel has to move.

</TheoryBlock>

## The arithmetic of whole-process swapping

The program below models five processes in 64 KB of memory, admits two of
them in sequence, and reports what the kernel paid in I/O. The transfer
rate is 10 MB/s — a round 1990s figure, chosen so the division can be
checked by hand.

```c
#include <stdio.h>

/* Whole-process swapping, with the arithmetic that made it obsolete.
 *
 * Before paging, memory held each process as one contiguous run and a
 * process either had a slot or did not. Admitting a fifth process when
 * four were resident meant copying an entire process to disk and
 * copying another back -- seconds of I/O to make room for something that
 * would itself block on the same disk a moment later.
 *
 * The point of the numbers below is the ratio: the cost of a swap is set
 * by the size of a process, and process sizes grew faster than disk
 * bandwidth did. */

#define MEMORY_KB 64
#define PROCESSES 5

struct process {
    const char *name;
    int size_kb;
    int resident;
};

/* A 10 MB/s transfer rate is a 1990s figure, kept round on purpose so
 * the arithmetic can be checked by hand. */
static double swap_ms(int size_kb)
{
    const double kb_per_ms = 10.0;
    return (double)size_kb / kb_per_ms;
}

static int memory_used(const struct process *p, int n)
{
    int total = 0;
    for (int i = 0; i < n; i++) {
        if (p[i].resident) {
            total += p[i].size_kb;
        }
    }
    return total;
}

static void show(const struct process *p, int n, const char *heading)
{
    int used = memory_used(p, n);

    printf("%s\n", heading);
    for (int i = 0; i < n; i++) {
        printf("  %-6s %3d KB  %s\n", p[i].name, p[i].size_kb,
               p[i].resident ? "resident" : "swapped out");
    }
    printf("  memory: %d of %d KB used, %d KB free\n\n", used, MEMORY_KB,
           MEMORY_KB - used);
}

/* Admit process `who` by evicting residents until it fits. Returns the
 * eviction cost in milliseconds. */
static double admit(struct process *p, int n, int who)
{
    double cost = 0.0;
    int used = memory_used(p, n);
    int need = p[who].size_kb;

    for (int i = 0; i < n && used + need > MEMORY_KB; i++) {
        if (i == who || !p[i].resident) {
            continue;
        }
        /* Swapping a process out costs one write, and it costs another
         * read to bring it back later -- but the return trip is charged
         * to whoever needs it, not to this admission. */
        cost += swap_ms(p[i].size_kb);
        p[i].resident = 0;
        used -= p[i].size_kb;
        printf("  evict %s (%d KB, %.1f ms)\n", p[i].name, p[i].size_kb,
               swap_ms(p[i].size_kb));
    }

    p[who].resident = 1;
    cost += swap_ms(need);
    printf("  swap in %s (%d KB, %.1f ms)\n", p[who].name, need,
           swap_ms(need));
    return cost;
}

int main(void)
{
    struct process procs[PROCESSES] = {
        {"editor", 20, 1},
        {"shell",  8, 1},
        {"build",  24, 1},
        {"log",    6, 1},
        {"test",   18, 0},
    };
    const int n = PROCESSES;

    show(procs, n, "initial state: 58 of 64 KB resident");

    printf("admitting test (18 KB) needs 12 KB more than is free\n");
    double first = admit(procs, n, 4);
    show(procs, n, "after admitting test");
    printf("  admission cost %.1f ms\n\n", first);

    /* The trap: the scheduler now runs editor again, and editor is the
     * process that was just swapped out. Admitting it evicts test -- the
     * process admitted a moment ago -- and the two take turns using the
     * disk. */
    printf("now the scheduler picks editor, which was just evicted\n");
    double second = admit(procs, n, 0);
    show(procs, n, "after admitting editor again");
    printf("  admission cost %.1f ms\n\n", second);

    double total = first + second;
    printf("%.1f ms of pure I/O for two admissions, and neither process\n",
           total);
    printf("has executed an instruction in between. That is the ping-pong\n");
    printf("the deck calls thrashing, in its pre-paging form.\n\n");

    printf("the fix was not a better eviction rule. It was a smaller unit:\n");
    printf("page a process in 4 KB pieces on demand and the same 18 KB\n");
    printf("process costs only the pages it actually touches.\n");
    return 0;
}
```

The first admission is the cheap-looking one. Memory holds 58 KB with
6 KB free, `test` needs 18 KB, so 12 KB must be found. Evicting `editor`
frees 20 KB — enough, with 8 KB left over. The cost is a 2.0 ms write
plus a 1.8 ms read, 3.8 ms, and afterward **memory is more full, not
less**: 56 KB used instead of 58. Nothing was freed; a process was moved.

The second admission is where it goes wrong. `editor` is needed again,
so `shell` (0.8 ms) and `build` (2.4 ms) go out to make 32 KB room, then
`editor` comes back (2.0 ms) for 5.2 ms. Afterward three of the five
processes are on disk, and the machine has done 9.0 ms of I/O for two
context switches and zero instructions of useful work. Repeat this at a
scheduler quantum of 10 ms and the machine spends most of its life
copying.

Notice what the program does *not* do: it does not claim a smarter victim
selection would help. Evicting `build` instead of `shell` and `build`
changes the individual numbers and not the pattern, because the pattern
comes from the unit being a whole process. If the working set genuinely
does not fit, no choice of victim makes it fit.

## Common pitfalls

### Thinking an eviction frees memory

It frees *resident* memory. The process still exists, still holds its
page table and its file descriptors, and still has to be read back. The
only thing that changed is where its bytes are, and the second admission
in the output above shows the bill arriving later, at a time chosen by
the scheduler rather than by the kernel.

### Measuring swap cost by the size of the binary

A 200-line C program that links against a GUI toolkit can have a resident
set of tens of megabytes. Cost follows the resident set, and the resident
set includes the heap, every thread's touched stack, and memory-mapped
files. Measure it — `time -l` or `/usr/bin/time -v` — rather than
estimating from `ls -l`.

### Ignoring the read-back leg

An eviction is one write. The process coming back is one read. Code that
budgets only the eviction halves the real cost, and the half it misses is
the half that runs synchronously when the scheduler picks that process
again.

### Assuming the kernel can always make room

If the largest process is bigger than total memory, no eviction helps and
the admission must fail. The program above silently assumes that case
away by letting the loop skip processes that cannot fit; a real kernel
returns an error or kills something, and the choice of which is a policy
decision, not an arithmetic one.

### Confusing swapping with paging

Swapping moves a process; paging moves a page. The names are used loosely
in conversation, and the loose usage hides the reason paging won: a 4 KB
transfer costs roughly the same as a 20 MB one on a rotating disk —
dominated by the seek — so moving the smaller unit wastes less of a fixed
price.
