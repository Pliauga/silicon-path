## The page you keep open

A cheatsheet is not a summary. It is the set of facts that are cheap to look up
and expensive to get wrong: the exact `printf` specifier for a `size_t`, the
precedence of `&` against `==`, whether `long` is four bytes here or eight.
Facts you can derive from first principles do not belong here; facts whose
wrong form compiles silently do.

Everything in the tables below is standard C11. The program at the end prints
the numbers that vary between platforms, so you can check the ones on *your*
machine rather than trusting a table written on someone else's.

## What you'll be able to do

- Pick the right `printf` specifier without guessing.
- State the precedence traps that actually cause bugs.
- Recognise the five undefined-behaviour patterns that appear most often.
- Check a platform's type sizes and limits with one compiled program.

## Types and their guaranteed minimums

| Type | Minimum size | Typical | Range if typical |
| --- | --- | --- | --- |
| `char` | 1 | 1 | −127..127 or 0..255 |
| `short` | 2 | 2 | ±32,767 |
| `int` | 2 | 4 | ±2,147,483,647 |
| `long` | 4 | 8 (LP64), 4 (LLP64) | ±9.2×10¹⁸ |
| `long long` | 8 | 8 | ±9.2×10¹⁸ |
| `float` | — | 4 | ~7 digits |
| `double` | — | 8 | ~15 digits |
| `size_t` | 2 | 8 | 0..2⁶⁴−1 |
| `ptrdiff_t` | 2 | 8 | ±2⁶³ |

The standard guarantees only the minimums and the ordering
`char ≤ short ≤ int ≤ long ≤ long long`. It does **not** guarantee that `int`
is 4 bytes, and code that assumes it is wrong on some embedded targets. Use
`<stdint.h>`'s `int32_t` when the width matters.

<TheoryBlock label="Why it matters for C" title="Every typedef here corresponds to a register">

	`int` is the machine's natural word — 32 bits on the x86 you are probably
	using, 16 on a 1970s minicomputer, 64 on some modern DSPs. `size_t` is the
	width of a pointer, because it must be able to express any object's size in
	the address space. `ptrdiff_t` is signed because a difference can be
	negative. These are not arbitrary choices; each one is a statement about the
	hardware the language was designed to describe.

</TheoryBlock>

## Operators by precedence, the ones that bite

| Level | Operators | Associativity | Trap |
| --- | --- | --- | --- |
| 1 | `()` `[]` `.` `->` `++` `--` (postfix) | left | `*p++` is `*(p++)` |
| 2 | `!` `~` `++` `--` (prefix) `*` `&` `sizeof` | right | `*p++` again |
| 3 | `*` `/` `%` | left | `%` on negatives truncates toward zero |
| 4 | `+` `-` | left | pointer + int is scaled |
| 5 | `<<` `>>` | left | shifting by ≥ width is UB |
| 6 | `<` `<=` `>` `>=` | left | |
| 7 | `==` `!=` | left | `a & b == c` is `a & (b == c)` |
| 8 | `&` | left | **below** `==`, the classic bug |
| 9 | `^` | left | |
| 10 | `\|` | left | |
| 11 | `&&` | left | short-circuits |
| 12 | `\|\|` | left | short-circuits |
| 13 | `?:` | right | |
| 14 | `=` `+=` etc. | right | `a = b = c` assigns c to b to a |
| 15 | `,` | left | |

Two rules cover most real bugs: **bitwise binds looser than comparison**, so
always parenthesise `(flags & MASK) == VALUE`; and **`sizeof` takes an
expression, not a type**, so `sizeof x` and `sizeof(x)` differ in meaning when
`x` is a type name in disguise.

## printf specifiers

| Type | Specifier | Note |
| --- | --- | --- |
| `int` | `%d` | |
| `unsigned` | `%u` | `%d` on an unsigned is UB for large values |
| `long` | `%ld` | missing `l` truncates on LP64 |
| `long long` | `%lld` | |
| `size_t` | `%zu` | `%d` prints garbage |
| `ptrdiff_t` | `%td` | |
| `intmax_t` | `%jd` | |
| `double` | `%f` `%e` `%g` | `%f` on a float promotes, so both are fine |
| `char` | `%c` | |
| string | `%s` | |
| pointer | `%p` | cast to `void *` first |
| hex | `%x` `%X` | |
| octal | `%o` | |
| `%` | `%%` | |

The `-Wall -Wextra` pair catches most of these because the compiler reads the
format string and checks the argument types. A cast that silences the warning
usually hides a real bug.

## The five undefined behaviours you will meet

| Pattern | Why it is UB | What to write instead |
| --- | --- | --- |
| signed overflow `INT_MAX + 1` | the standard permits any result | check first, or compute in `unsigned` |
| `arr[5]` on a 5-element array | out of bounds, no check | bound the index |
| `x << 32` on a 32-bit `int` | shift ≥ width | mask the count |
| reading an uninitialised variable | indeterminate value | initialise or restructure |
| `free(p); free(p);` | double free | set `p = NULL` after freeing |
| `printf("%d", d)` for `double` | wrong type in varargs | `%f` |

Undefined behaviour is not "it crashes." It is "the compiler may assume it
never happens" — which means an `if (x + 1 < x)` overflow check can be deleted
by the optimiser, because a correct program cannot overflow.

## One program, your platform's numbers

```c
#include <float.h>
#include <limits.h>
#include <stdint.h>
#include <stdio.h>

/* The numbers a C programmer should never guess: type sizes, integer limits,
 * and the traps that follow from them. Everything printed here comes from
 * <limits.h>, <float.h> and sizeof on this machine — the point of running it
 * is that several values differ between platforms. */

struct packed_pair {
    char  c;
    int   i;
};

struct reordered_pair {
    int   i;
    char  c;
};

struct three_fields {
    char   a;
    short  b;
    int    c;
};

int main(void) {
    printf("=== type sizes (bytes) ===\n");
    printf("%-16s %s\n", "type", "sizeof");
    printf("%-16s %s\n", "char", "1 (guaranteed by the standard)");
    printf("%-16s %zu\n", "short", sizeof(short));
    printf("%-16s %zu\n", "int", sizeof(int));
    printf("%-16s %zu\n", "long", sizeof(long));
    printf("%-16s %zu\n", "long long", sizeof(long long));
    printf("%-16s %zu\n", "float", sizeof(float));
    printf("%-16s %zu\n", "double", sizeof(double));
    printf("%-16s %zu\n", "void *", sizeof(void *));
    printf("%-16s %zu\n", "size_t", sizeof(size_t));

    printf("\n=== fixed-width types are guaranteed ===\n");
    printf("int8_t %zu, int16_t %zu, int32_t %zu, int64_t %zu\n",
           sizeof(int8_t), sizeof(int16_t), sizeof(int32_t), sizeof(int64_t));

    printf("\n=== integer limits ===\n");
    printf("%-22s %d\n", "INT_MAX", INT_MAX);
    printf("%-22s %d\n", "INT_MIN", INT_MIN);
    printf("%-22s %u\n", "UINT_MAX", UINT_MAX);
    printf("%-22s %ld\n", "LONG_MAX", LONG_MAX);
    printf("%-22s %lld\n", "LLONG_MAX", LLONG_MAX);
    printf("%-22s %zu\n", "SIZE_MAX", SIZE_MAX);

    printf("\n=== floating point ===\n");
    printf("%-22s %d\n", "FLT_DIG (decimal)", FLT_DIG);
    printf("%-22s %d\n", "DBL_DIG (decimal)", DBL_DIG);
    printf("%-22s %d\n", "FLT_MAX_EXP", FLT_MAX_EXP);
    printf("%-22s %d\n", "DBL_MAX_EXP", DBL_MAX_EXP);

    printf("\n=== the overflow trap ===\n");
    int big = INT_MAX;
    printf("INT_MAX            = %d\n", big);
    printf("INT_MAX + 1 wraps  = %d   (signed overflow is undefined)\n",
           (int)((unsigned)big + 1u));
    unsigned ubig = UINT_MAX;
    printf("UINT_MAX           = %u\n", ubig);
    printf("UINT_MAX + 1 wraps = %u   (unsigned wraps, defined)\n", ubig + 1u);

    printf("\n=== struct padding ===\n");
    printf("struct { char; int; }        %zu bytes\n", sizeof(struct packed_pair));
    printf("struct { int; char; }        %zu bytes\n", sizeof(struct reordered_pair));
    printf("struct { char; short; int; } %zu bytes\n", sizeof(struct three_fields));
    printf("char + int would be 5 if packed; padding makes it %zu\n",
           sizeof(struct packed_pair));

    printf("\n=== pointer arithmetic ===\n");
    int arr[5] = {10, 20, 30, 40, 50};
    /* Addresses themselves vary per run (ASLR), so compare positions
       rather than print them. The byte distance is what matters. */
    printf("&arr[1] - &arr[0] = %td elements, %td bytes\n",
           &arr[1] - &arr[0],
           (char *)&arr[1] - (char *)&arr[0]);
    printf("an int* advances by sizeof(int) = %zu bytes per step\n", sizeof(int));
    printf("*(arr + 2)   = %d\n", *(arr + 2));
    printf("2[arr]       = %d  (same as *(arr + 2))\n", 2[arr]);
    printf("&arr[4]-&arr[0] = %td elements\n", &arr[4] - &arr[0]);
    printf("(void *)ptr + 1 advances 1 byte; an int* + 1 advances %zu\n",
           sizeof(int));

    printf("\n=== printf specifiers ===\n");
    int    i = -42;
    unsigned u = 42u;
    double d = 3.14159265358979;
    char   s[] = "text";
    char   ch = 'A';
    printf("int      %%d      %d\n", i);
    printf("unsigned %%u      %u\n", u);
    printf("hex      %%x      %x\n", u);
    printf("octal    %%o      %o\n", u);
    printf("char     %%c      %c\n", ch);
    printf("string   %%s      %s\n", s);
    printf("double   %%f      %f\n", d);
    printf("double   %%.3f    %.3f\n", d);
    printf("double   %%e      %e\n", d);
    printf("double   %%g      %g\n", d);
    printf("size_t   %%zu     %zu\n", sizeof d);
    printf("ptrdiff  %%td     %td\n", &arr[4] - &arr[0]);
    printf("pointer  %%p      (an address)\n");

    return 0;
}
```

This is an LP64 machine — Linux and macOS both are. On Windows (LLP64) `long`
is 4 bytes and `LONG_MAX` is 2147483647. That is not a different compiler
being wrong; it is the standard permitting both. If a program must produce the
same output on both, it cannot use `long` for anything where the range matters.

## Loop and control idioms

| Idiom | Meaning |
| --- | --- |
| `for (size_t i = 0; i < n; i++)` | counting up, unsigned |
| `for (i = n; i-- > 0; )` | counting down without underflow |
| `while ((c = getchar()) != EOF)` | assignment in condition, parenthesised |
| `do { } while (0)` | a macro that behaves as one statement |
| `if (p)` / `if (!p)` | null test, never `if (p == NULL)` in a hot path |
| `switch` with no `default` | misses new enum members in silence |

## Common pitfalls

### `sizeof` on a function parameter

An array parameter decays to a pointer, so `sizeof arr` inside the function is
the pointer size. Pass the element count as a second argument, always.

### `%d` with `size_t`

On LP64, `size_t` is 8 bytes and `%d` reads 4, so the remaining 4 are taken
from the next argument. The output is garbage or the program crashes. `%zu` is
the fix and `-Wformat` will tell you.

### `scanf("%d", x)` instead of `&x`

Compiles with a warning under `-Wall`, and the warning is the only thing
standing between the program and a segfault. Read the warning, do not cast it
away.

### Assuming `char` is signed

It is signed on x86 and unsigned on ARM by default. Code that stores a byte
value above 127 in a `char` and compares it to a negative number behaves
differently on the two. Use `unsigned char` for bytes, `char` for text.
