## A circuit that remembers

Everything in the last module was combinatorial: feed in inputs, get an
answer, forget. A gate has no past. That is fine for an adder, which
computes the same sum from the same inputs every time, and useless for
anything that needs to count.

To remember one bit you need a circuit whose output feeds back into its
own input. Two gates cross-coupled — each one's output is the other's
input — settle into one of two stable states and stay there until
disturbed. That is the whole idea of a **latch**: a loop with two resting
positions.

A **flip-flop** is a latch with a gatekeeper. A latch is *level-sensitive*:
while its enable input is high it is transparent, and its output follows
its input. A flip-flop is *edge-triggered*: it samples its input only at
the instant the clock line rises, and ignores it the rest of the cycle.

That distinction is the reason the CPU has a clock at all. The edge is a
contract: state changes here, and nowhere else.

- Say why a clock signal makes a processor's behaviour reproducible.

## Two inputs, one stored bit

The simplest usable storage element is the **D flip-flop**. It has one
data input `D`, one clock input, and one stored output `Q`. On a rising
edge, `Q` becomes whatever `D` was. Between edges, nothing happens.

| Time     | D | Clock edge? | Q after |
| -------- | - | ----------- | ------- |
| t0       | 1 | no          | 0       |
| t1       | 1 | rising      | 1       |
| t2       | 0 | no          | 1       |
| t3       | 0 | rising      | 0       |

Two things in that table are worth naming. The value on the left of an
edge is *ignored*, and the value between edges is *irrelevant*. A
flip-flop only ever reads `D` at the moment marked "rising". Everything a
digital machine does is built on that narrow instant.

<TheoryBlock label="Why it matters for C" title="Every variable is a pile of these">

	When you declare `int counter = 0;` the compiler is reserving 32
	flip-flops somewhere — in a register if it is hot, in memory if it is
	not. Assigning to the variable is, at the bottom, driving those
	flip-flops' inputs and waiting for an edge. This is also why `volatile`
	exists: the compiler must not assume the value it read a moment ago is
	still there if something outside the program can change the underlying
	flip-flops.
</TheoryBlock>

## The edge is the whole contract

Because a flip-flop only updates on the edge, the timing of the clock
decides the timing of the entire machine. A 3 GHz core has an edge every
third of a nanosecond; a 1 Hz blinking LED has one per second. The
circuit is the same. Only the clock differs.

<details>
<summary>Accessible version — the same trace as a list</summary>

- Edge 1: `D = 1`, `Q` was 0, `Q` becomes 1.
- Edge 2: `D = 0`, `Q` was 1, `Q` becomes 0.
- Edge 3: `D = 1`, `Q` was 0, `Q` becomes 1.
- Edge 4: `D = 1`, `Q` was 1, `Q` stays 1.

</details>

## Modelling a flip-flop in C

A program cannot observe a wire. What it can do is model the *rule*: one
byte of state, one function that applies the edge.

```c
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>

/* One D flip-flop: a single stored bit, updated only on a clock edge. */
struct dff {
    uint8_t q; /* the stored bit — the only state the circuit keeps */
    uint8_t d; /* the input waiting for the next edge */
};

/* The edge is the contract: q may change here and nowhere else. */
static void clock_edge(struct dff *ff) {
    ff->q = (uint8_t)(ff->d & 0x01u);
}

int main(void) {
    struct dff ff = {0, 0};
    const uint8_t samples[8] = {1, 0, 1, 1, 0, 0, 1, 0};

    printf("edge  d  q before  q after\n");
    for (size_t i = 0; i < sizeof samples; i++) {
        uint8_t before = ff.q;
        ff.d = samples[i];
        clock_edge(&ff);
        printf("%4zu  %u      %u        %u\n", i + 1, ff.d, before, ff.q);
    }
    return 0;
}
```

`q` is the only field that survives between edges; `d` is just the wire
waiting to be sampled. `clock_edge` is the entire behaviour of the
device, and it is four lines long. That is not a simplification for the
lesson — a real D flip-flop's logic is about that small.

## Expected output

```text
edge  d  q before  q after
   1  1      0        1
   2  0      1        0
   3  1      0        1
   4  1      1        1
   5  0      1        0
   6  0      0        0
   7  1      0        1
   8  0      1        0
```

Read line 4. `D` was 1 and `Q` was already 1, so `Q` did not change. An
edge with the same value on both sides is a no-op, and that is normal:
most edges in a real processor write back a value the register already
holds.

## Common pitfalls

### Reading the input in the wrong order

```c
ff.d = samples[i];
clock_edge(&ff);
```

The assignment must come *before* the edge, because the flip-flop samples
`D` at the instant of the edge. Writing `clock_edge` first stores last
cycle's input, and the trace shifts by one row. If the first output line
shows the previous iteration's bit, check this ordering first.

### Confusing a latch with a flip-flop

A latch marked "transparent while enabled" is not a flip-flop. If you
model a latch and then reason about it as though it sampled on an edge,
you will predict a value that the real circuit never holds. When the
enable is high, the output *follows* the input continuously; there is no
stored value to reason about until the enable falls.

### Assuming a real flip-flop is instantaneous

The model updates `q` in zero time. Real gates have a propagation delay —
tens of picoseconds today, but not zero — and a circuit whose feedback
path is too slow can oscillate instead of settling. That is a
**metastability** failure, and it is why real designs specify setup and
hold times around every clock edge.
