## The first circuit with a history

A counter is what you get when you feed a flip-flop's output back into an
adder and store the sum. On every clock edge the stored value increases
by one, so the circuit's output depends not only on its input but on how
many edges have arrived. That is the difference between *combinatorial*
and *sequential* logic, and a counter is the smallest thing that
demonstrates it.

The interesting part is not the counting. It is what happens at the top.
A four-bit counter holds values 0 through 15. On the sixteenth edge it
has no sixteenth bit to carry into, so it wraps to zero. This is not a
design flaw, it is the definition, and it is the same wrap you will meet
again in C when an `unsigned int` overflows.

## What you'll be able to do

- Explain how a counter differs from a combinatorial adder.
- Model a four-bit counter with an explicit mask.
- Predict the wrap point and the number of states for a given width.
- Relate a hardware counter's wrap to unsigned overflow in C.

## Width decides the range

A counter with *n* flip-flops holds *n* bits and has 2^n states. The
number of distinct values is the number of patterns, not one more than
the largest; a four-bit counter counting 0 to 15 has sixteen states and
returns to zero on the sixteenth tick.

| Width | States | Counts from | to  | Mask    |
| ----- | ------ | ----------- | --- | ------- |
| 4     | 16     | 0           | 15  | `0x0f`  |
| 8     | 256    | 0           | 255 | `0xff`  |
| 16    | 65,536 | 0           | 65,535 | `0xffff` |

The mask column is the whole implementation. To add one in a fixed width,
add and then discard everything above the top bit: `(value + 1) & 0x0f`.
The AND is not a safety check — it *is* the carry-out wire, tied to
nothing.

<TheoryBlock label="Why it matters for C" title="Overflow is not an error, it is a width">

	An unsigned `int` in C wraps at 2^32 for exactly this reason: the
	hardware adder has 32 bit positions and drops the carry. Signed overflow
	is different — the C standard calls it undefined behaviour — but the
	unsigned case is the counter you just built. When you write `x & 0xff`
	you are picking the low eight flip-flops out of thirty-two.
</TheoryBlock>

## Building one in C

The struct holds the value. The tick function applies the edge. The mask
keeps the invariant `value < 16` true, and wrapping is a side effect we
count separately so the reader can see it happen.

```c
#include <stdint.h>
#include <stdio.h>

/* A 4-bit counter is one register plus one adder. The mask is the whole
 * trick: without it, 1111 + 1 would need a fifth bit. */

#define WIDTH 4u
#define MASK  ((1u << WIDTH) - 1u)

struct counter4 {
    uint8_t value; /* always in 0..15 — the invariant the mask keeps */
    unsigned wraps;
};

static void tick(struct counter4 *c) {
    uint8_t next = (uint8_t)((c->value + 1u) & MASK);
    if (next == 0u) {
        c->wraps++;
    }
    c->value = next;
}

static void print_bits(uint8_t v) {
    for (int i = (int)WIDTH - 1; i >= 0; i--) {
        putchar(((v >> (unsigned)i) & 1u) ? '1' : '0');
    }
}

int main(void) {
    struct counter4 c = {0, 0};

    printf("tick  bits  value  wraps\n");
    for (unsigned t = 0; t <= 19u; t++) {
        printf("%4u  ", t);
        print_bits(c.value);
        printf("  %5u  %5u\n", (unsigned)c.value, c.wraps);
        tick(&c);
    }

    printf("mask for %u bits: 0x%X\n", WIDTH, MASK);
    printf("states: %u\n", MASK + 1u);
    printf("bytes stored: %zu\n", sizeof c);
    return 0;
}
```

Note that the loop prints *then* ticks, so line `t` shows the value before
the `t`-th edge. That ordering matters when you compare against the
output.

Two details in the tail of that output are worth reading twice.

`bytes stored: 8` — a struct with a `uint8_t` and an `unsigned` does not
occupy five bytes. The `unsigned` wants four-byte alignment, so the
compiler inserts three bytes of padding after `value`. You will meet this
again in the next module; for now just note that the *logical* state is
one byte and the *stored* layout is two fields.

And the wrap counter reaches 1 at tick 16, not 15. The value printed on
line 16 is `0000`, and the wrap has already happened.

## Common pitfalls

### Forgetting the mask and relying on the variable's width

```c
uint8_t next = (uint8_t)(c->value + 1u);   /* wraps, but by accident */
```

This works because `uint8_t` conversion truncates — but it hides the
mechanism, and it breaks the moment someone widens the counter to
`unsigned`. Make the mask explicit. The reader should be able to see the
carry being discarded, not infer it from a type.

### Off-by-one in the state count

A four-bit counter has **16** states, not 15. The value 0 is a state. The
commonest wrong answer to "how many values fit in n bits" is `2^n - 1`.
Both endpoints are included: 0 through 15.

### Assuming the wrap is an error to be caught

In hardware there is nothing to catch; the carry simply has nowhere to go.
If your program needs to detect that it happened, you have to compare
before and after, as `tick` does with `next == 0u`. Wrapping is an
*observation*, not a fault.
