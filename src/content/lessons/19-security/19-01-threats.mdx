## What you are defending, from whom, and at what cost

A security discussion that starts with a technique — a cipher, a firewall rule,
a library — has already skipped the only question that matters. A **threat
model** is three sentences: what asset is being protected, who wants it, and
what it costs them to get it. Without all three you cannot say whether a control
is worth its price, because there is no price to compare against.

The asset might be a file, a session cookie, a credit card number, or the
ability to run code on a machine. The adversary might be a bored person on the
same network, a criminal with a rented botnet, or a nation state. The cost is
measured in guesses per second, in dollars, or in the risk of being caught.
Different answers give completely different designs.

This lesson is about the arithmetic that comes before any code. It is exactly
the same arithmetic as the last module — exponents and rates — applied to an
adversary instead of a disk.

## What you'll be able to do

- State a threat model in three sentences and identify which part is missing.
- Compute the size of a keyspace from its alphabet and length.
- Convert that keyspace into a time given a guessing rate.
- Say why "use a strong password" is an engineering answer and not a moral one.

## Three properties, and you rarely get all three

Security people describe the goals with three words that are easy to confuse.

| Property | Question it answers | Broken by |
| --- | --- | --- |
| **Confidentiality** | who may read this? | a cipher that leaks, a file with mode `0644` |
| **Integrity** | who may change this? | a hash collision, an unsigned update |
| **Availability** | can the reader get it at all? | a flood, a full disk, a single server |

Every real incident breaks at least one, and many break a different one than
the designers worried about. Ransomware is an availability attack that arrives
through a confidentiality failure. A supply-chain compromise usually breaks
integrity while leaving the other two untouched.

## The keyspace is the whole argument

Suppose a secret has `A` possible symbols per position and `L` positions. The
number of candidate secrets is `A^L`. If an attacker can test `R` candidates
per second, exhausting the space takes `A^L / R` seconds. That is the entire
model.

What makes it useful is how fast it grows. Adding one character to an
eight-character lowercase password multiplies the work by 26. Going from
lowercase-only to the printable ASCII set multiplies it by roughly 3.6 — the
same as adding more than one character, for free.

| Secret | Alphabet | Length | Keyspace |
| --- | --- | --- | --- |
| 4-digit PIN | 10 | 4 | 10,000 |
| 6 lowercase | 26 | 6 | 308,915,776 |
| 8 lowercase | 26 | 8 | 208,827,064,576 |
| 8 lower + digit | 36 | 8 | 2,821,109,907,456 |
| 8 mixed | 94 | 8 | 6,095,689,385,410,816 |
| 12 mixed | 94 | 12 | 4.76 × 10²³ |

Note what did *not* help: choosing an unusual word. The model above assumes the
attacker must try every string, and a dictionary attack invalidates that
assumption for human-chosen secrets. This is why the advice moved from
"complexity" to "length", and why a four-word passphrase beats `P@ssw0rd1`.

<TheoryBlock label="Why it matters for C" title="The rate is a property of your code">

	`R` is not a constant of nature. If your program compares a password with
	`strcmp`, an attacker learns where the first mismatch is from the timing, and the
	effective `R` collapses. If you hash with a deliberately slow function, you choose
	`R` and you can lower it by four orders of magnitude. Rate limiting, lockouts, and
	slow hashes are all the same lever: make each guess expensive. They are cheaper to
	implement than any cipher and they change the answer to the only equation that
	matters.

</TheoryBlock>

## Computing the answer

The program below is the threat model as arithmetic. It does not try anything;
it computes how long an attacker with a given rate would need, and prints the
unit that makes the number readable.

```c
#include <stdio.h>
#include <stdint.h>

/* Brute force arithmetic. An attacker who can try `rate` guesses per second
   needs (keyspace / rate) seconds to exhaust a space of `keyspace` secrets.
   Integers, not guesses: this is the whole threat model in three columns. */

struct case_study {
    const char *label;
    unsigned alphabet;   /* how many distinct symbols a character can be */
    unsigned length;     /* how many characters the secret has */
    double   rate;       /* guesses per second the attacker can afford */
};

static void print_duration(double seconds) {
    if (seconds < 1.0) {
        printf("%12.3f ms", seconds * 1000.0);
    } else if (seconds < 120.0) {
        printf("%12.3f s", seconds);
    } else if (seconds < 172800.0) {
        printf("%12.3f h", seconds / 3600.0);
    } else if (seconds < 3.0e9) {
        printf("%12.3f y", seconds / 31536000.0);
    } else {
        printf("%12.3e y", seconds / 31536000.0);
    }
}

int main(void) {
    const struct case_study cases[] = {
        {"4 digits, PIN",        10,    4, 1e9},
        {"6 lowercase",          26,    6, 1e9},
        {"8 lowercase",          26,    8, 1e9},
        {"8 lower+digit",        36,    8, 1e9},
        {"8 mixed",              94,    8, 1e9},
        {"12 mixed",             94,   12, 1e9},
        {"12 mixed, slow hash",  94,   12, 1e4}
    };
    const size_t count = sizeof cases / sizeof cases[0];

    printf("%-22s %6s %20s   %s\n", "secret", "length", "keyspace", "time to exhaust");
    printf("%-22s %6s %20s   %s\n", "----------------------",
           "------", "--------------------", "----------------");

    for (size_t i = 0; i < count; i++) {
        double keyspace = 1.0;
        for (unsigned k = 0; k < cases[i].length; k++) {
            keyspace *= (double)cases[i].alphabet;
        }
        printf("%-22s %6u %20.0f   ", cases[i].label, cases[i].length, keyspace);
        print_duration(keyspace / cases[i].rate);
        printf("\n");
    }

    /* One more symbol multiplies the search space by the alphabet size. */
    printf("\none extra character at 94 symbols:\n");
    double keyspace = 1.0;
    for (unsigned k = 0; k < 8; k++) {
        keyspace *= 94.0;
    }
    for (unsigned extra = 0; extra <= 3; extra++) {
        printf("length %2u: %20.0f keys   ", 8u + extra, keyspace);
        print_duration(keyspace / 1e9);
        printf("\n");
        keyspace *= 94.0;
    }

    return 0;
}
```

Read the first row against the last. A four-digit PIN falls in a hundredth of a
millisecond at a billion guesses per second, which is roughly what one modern
GPU does against a fast hash. Twelve characters drawn from the full printable
set takes fifteen million years — until the last row, where the same secret at
a deliberately slow hash rate takes fifteen trillion. The secret did not
change. Only `R` moved.

The second table shows the same multiplication at work: each extra character
multiplies the work by 94, so length 8 to length 11 is a factor of 830,000. Four
more characters bought more than any complexity rule ever written.

The unit switch in `print_duration` is not decoration. A raw number like
`1.509e+12` years means nothing to a reader; "longer than the age of the
universe" lands. A good threat model always names the unit that makes the
comparison obvious.

## Common pitfalls

### Choosing a control before writing the model

"We should encrypt it" is not a threat model. Encrypting a file whose real
problem is that the backups are world-readable moves the attacker's work from
zero to zero. Write the three sentences first; half the controls you were
about to add become obviously irrelevant, and one you had not considered
becomes obvious.

### Treating the keyspace as the only factor

`A^L` assumes independent, uniformly random symbols and an attacker who has to
enumerate. Human passwords violate both: they are drawn from a small set of
patterns, and attackers use that set. A twelve-character password like
`password1234` has a keyspace of about 10²⁴ by the formula and a few thousand
by the dictionary.

### Measuring security by the algorithm alone

The same cipher is strong or useless depending on the key. AES-256 with a key
derived from a four-digit PIN is a four-digit secret with extra steps. When you
read that a system "uses AES-256", the next question is where the key came
from, and it is usually the interesting one.

### Believing a slow hash makes a weak password safe

It multiplies the attacker's cost by a constant. That is worth having — the
last row of the table shows a factor of 10⁵ — but it does not rescue a secret
with a keyspace of 10,000. Slow hashing and long secrets are complementary,
not substitutes.
