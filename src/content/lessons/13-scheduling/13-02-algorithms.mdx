## The three that matter

Every scheduling policy is a rule for choosing one process from the ready queue.
Three rules cover the lecture and most of what real kernels approximate:

| Policy | Rule | Strength | Weakness |
| --- | --- | --- | --- |
| FCFS | run in arrival order, no preemption | trivial, no starvation | long job blocks everything behind it |
| SJF | shortest service time first | provably lowest average wait | needs to know the future |
| Round robin | fixed quantum, then back of queue | responsive, fair | more context switches |

SJF's weakness is the interesting one. It minimizes average waiting time — that
is a theorem, not an opinion — but it needs each process's service time before it
runs, which no kernel knows. Real systems *estimate* the next burst from the last
one, and the estimate is wrong often enough that the guarantee evaporates.

Round robin trades the optimum for something achievable. A **quantum** of a few
milliseconds means no process waits long for its first slice, at the cost of
switching more often.

## What you'll be able to do

- Simulate FCFS, SJF, and round robin over an array of process structs.
- Compute waiting time as turnaround minus service, and average it correctly.
- Explain why SJF is optimal yet unused, and why round robin wins anyway.
- Predict how changing the quantum moves the average wait.

<TheoryBlock label="Why it matters for C" title="Waiting time is turnaround minus service">

	The definitions are easy to garble. Turnaround is finish time minus arrival; waiting is turnaround
	minus service. For a process that arrives at 0, runs 10 ms, and finishes at 10 ms, turnaround is
	10 and waiting is 0 — it never waited. Every average in this lesson uses those definitions, and if
	your numbers disagree with a textbook, check which definition the textbook used before assuming
	a bug.
</TheoryBlock>

## Three policies, one workload

```c
#include <stdio.h>

/* Three scheduling policies over the same five processes.
   Arrival time is when a process becomes runnable.
   Service time is how much CPU it needs, in milliseconds.
   Waiting time is turnaround minus service, the standard definition. */

#define COUNT 5

struct process {
    const char *name;
    int arrival;
    int service;
};

struct stats {
    double avg_wait;
    double avg_turnaround;
};

static struct stats summarise(int wait_total, int turn_total, int n) {
    struct stats s;
    s.avg_wait = (double)wait_total / n;
    s.avg_turnaround = (double)turn_total / n;
    return s;
}

/* First come, first served: arrival order, no preemption. */
static struct stats fcfs(const struct process *p, int n) {
    int clock = 0;
    int wait_total = 0;
    int turn_total = 0;

    for (int i = 0; i < n; i++) {
        if (clock < p[i].arrival) {
            clock = p[i].arrival;           /* CPU idles until it arrives */
        }
        clock += p[i].service;
        int turnaround = clock - p[i].arrival;
        int wait = turnaround - p[i].service;

        printf("  %-3s wait %3d ms  finish %3d ms\n", p[i].name, wait, clock);
        wait_total += wait;
        turn_total += turnaround;
    }
    return summarise(wait_total, turn_total, n);
}

/* Shortest job first, non-preemptive: at each decision point pick the
   ready process with the smallest service time.                    */
static struct stats sjf(const struct process *p, int n) {
    int done[COUNT] = { 0 };
    int clock = 0;
    int wait_total = 0;
    int turn_total = 0;

    for (int step = 0; step < n; step++) {
        int pick = -1;
        for (int i = 0; i < n; i++) {
            if (done[i] || p[i].arrival > clock) {
                continue;
            }
            if (pick < 0 || p[i].service < p[pick].service) {
                pick = i;
            }
        }
        if (pick < 0) {
            clock++;                        /* nothing ready yet */
            step--;
            continue;
        }

        clock += p[pick].service;
        int turnaround = clock - p[pick].arrival;
        int wait = turnaround - p[pick].service;
        done[pick] = 1;

        printf("  %-3s wait %3d ms  finish %3d ms\n",
               p[pick].name, wait, clock);
        wait_total += wait;
        turn_total += turnaround;
    }
    return summarise(wait_total, turn_total, n);
}

/* Round robin: each ready process runs at most `quantum` ms, then joins
   the back of the queue. Waiting time is measured at completion.    */
static struct stats round_robin(const struct process *p, int n, int quantum) {
    int remaining[COUNT];
    int clock = 0;
    int wait_total = 0;
    int turn_total = 0;
    int finished = 0;

    for (int i = 0; i < n; i++) {
        remaining[i] = p[i].service;
    }

    while (finished < n) {
        int ran_something = 0;

        for (int i = 0; i < n; i++) {
            if (remaining[i] <= 0 || p[i].arrival > clock) {
                continue;
            }
            ran_something = 1;

            int slice = remaining[i] < quantum ? remaining[i] : quantum;
            clock += slice;
            remaining[i] -= slice;

            if (remaining[i] == 0) {
                finished++;
                int turnaround = clock - p[i].arrival;
                int wait = turnaround - p[i].service;
                wait_total += wait;
                turn_total += turnaround;
                printf("  %-3s wait %3d ms  finish %3d ms\n",
                       p[i].name, wait, clock);
            }
        }

        if (!ran_something) {
            clock++;                        /* idle tick before next arrival */
        }
    }
    return summarise(wait_total, turn_total, n);
}

int main(void) {
    const struct process procs[COUNT] = {
        { "P1", 0, 10 },
        { "P2", 1, 4 },
        { "P3", 2, 6 },
        { "P4", 3, 2 },
        { "P5", 4, 8 },
    };

    printf("workload:");
    for (int i = 0; i < COUNT; i++) {
        printf(" %s(arr %d, svc %d)", procs[i].name,
               procs[i].arrival, procs[i].service);
    }
    printf("\n");

    printf("\nfirst come, first served:\n");
    struct stats f = fcfs(procs, COUNT);

    printf("\nshortest job first:\n");
    struct stats s = sjf(procs, COUNT);

    printf("\nround robin, quantum 4:\n");
    struct stats r = round_robin(procs, COUNT, 4);

    printf("\n%-10s %10s %15s\n", "policy", "avg wait", "avg turnaround");
    printf("%-10s %10.1f %15.1f\n", "FCFS", f.avg_wait, f.avg_turnaround);
    printf("%-10s %10.1f %15.1f\n", "SJF", s.avg_wait, s.avg_turnaround);
    printf("%-10s %10.1f %15.1f\n", "RR (q=4)", r.avg_wait, r.avg_turnaround);
    return 0;
}
```

Three implementation notes. `step--` inside the SJF loop is how "the CPU idled"
is expressed without a second clock advance: the step is retried after time moves
on. The round-robin loop scans the array in index order each pass, which makes
the policy deterministic — a real scheduler would use a FIFO queue and arrival
ordering would matter.

The result that surprises people: **round robin has the worst average waiting
time here**, 12.8 against SJF's 10.0. It is still the policy real systems use.
Average wait is the wrong metric when the goal is responsiveness — round robin's
longest single wait is 20 ms, while FCFS makes P5 sit for 18 ms behind four
processes and would make it sit far longer with a bigger workload.

Every number above is a pure function of the table. There is no clock in this
program and no thread; it is arithmetic over structs, so it prints the same thing
every time on every machine. That is exactly why scheduling is worth simulating
before you trust a policy.

## Common pitfalls

### Comparing policies on a workload that flatters one

SJF wins on this workload because the shortest jobs happen to arrive late. Reverse
the arrival order — all jobs ready at time 0, shortest last — and the gap widens.
Reshuffle so the longest job arrives first and SJF's advantage shrinks. Any claim
that one policy is better needs the workload stated with it.

### Forgetting the idle case

If nothing has arrived when the clock reaches its next value, the CPU must idle.
FCFS handles it with `clock = p[i].arrival`; SJF and round robin need an explicit
tick. Skip that and the simulation invents work that cannot happen, and the
numbers look plausible while being wrong.

### Using completion time as waiting time

`finish - arrival` is turnaround. Waiting is `turnaround - service`. The summary
table above is the one to sanity-check: if a process finished at 10 having
arrived at 0 and needing 10, its wait must be 0, not 10. If your table shows 10,
the subtraction is missing.

### Hardcoding COUNT into the loops but not into the arrays

`int done[COUNT]` and `int remaining[COUNT]` are fine here because the arrays are
fixed. Pass a larger `n` and both overflow. In real code the arrays are allocated
from `n`, or `n` is asserted against `COUNT` at the top of the function.
